# PROJECT.md — память проекта

## Название и цель

- Рабочее название: Drink Company. Финальное название будет выбрано отдельно.
- Пользовательская проблема: игры про производство напитков обычно сводят рецептуру к готовым рецептам или линейным бонусам.
- Основной пользователь: игрок, которому интересны производство, рецептуры, рынок и постепенное развитие компании.
- Ключевой результат: каждая партия создаётся решениями игрока, а её коммерческий результат зависит от продукта и конкретных покупателей.

## Текущий статус

- Версия: 0.8.0
- Работает: создание компании, производство пива и сидра, оборудование, глубокие рецептуры, партии, дегустация, розлив, 12 постоянных точек сбыта, переговоры и продажи, 12 компаний мира, компактная мобильная навигация, динамический спрос, повторные заказы, стабильность следующих партий, отзывы конечных покупателей, живые релизы компаний, поставщики, складские лоты, закупки, фактическая себестоимость, развитие объекта, помещения, инфраструктура, износ, санитария, производственная очередь, обязательная проверка версии PWA, бренды, упаковка, коммерческие релизы, продвижение, IndexedDB и JSON-экспорт.
- Ближайшая цель: собственный бар, фирменный магазин и прямые продажи.

## Стек

- Языки: TypeScript, CSS, HTML.
- Клиент: React + Vite.
- Сервер: отсутствует.
- Хранилище: IndexedDB, JSON-экспорт.
- Инфраструктура: GitHub Pages, PWA, GitHub Actions.
- Тесты: Vitest.

## Архитектура

- Доменные модули: игра, производство, объект, снабжение, рецепты, партии, рынок, бренд, продвижение, архив, команда.
- Источник истины: единый `GameState` версии 8 в доменном слое.
- Производственные расчёты: `src/domain/production.ts`, без зависимости от React.
- UI: только отображает состояние и вызывает доменные переходы.
- Миграция: сохранения schemaVersion 1–7 автоматически переходят на schemaVersion 8.
- Критические данные: деньги, оборудование, рецепты, партии, складские лоты, закупки, поставщики, бутылочный склад, история мира, сотрудники, кандидаты, смены и фонд оплаты труда.

## Ограничения

- Главная платформа: телефон, вертикальная ориентация.
- Без аккаунтов и сервера.
- PWA устанавливается, полный офлайн не гарантируется.
- Запрещено: Godot, GDScript, зависимость проекта от Cursor, бизнес-логика в UI, фиксированные оптимальные рецепты.
