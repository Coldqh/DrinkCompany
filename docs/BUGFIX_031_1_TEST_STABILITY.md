# Bugfix 031.1 — Test Stability and Observer Performance

## Проблема

После Cocktail Market и Premium Interface четыре проверки падали в общем запуске: одна из-за неверного ожидания остатка, три из-за конкуренции CPU-тяжёлых симуляций за ресурсы одного CI runner. Observer дополнительно замедлялся квадратичными проходами по накопленной истории kernel.

## Исправление

- прямой тест поставки проверяет физический остаток 24 бутылки до начала смены;
- сезонная аграрная проверка вызывает владельца логики `advancePrimaryProductionDay`, а не весь мир;
- Vitest запускает файлы последовательно, сохраняя изоляцию тестов и исключая CPU contention;
- observer-тест имеет явный бюджет 90 секунд для девятимесячной интеграционной симуляции;
- Hospitality Market использует индексы assets, venues, organizations и menu items на один дневной тик;
- kernel использует наборы уже записанных источников и обновляет parent trace nodes одним проходом.

## Инварианты

- поставка не создаёт дополнительную бутылку;
- оптимизация не меняет состояние симуляции;
- денежные и товарные записи остаются идемпотентными;
- существующие trace node IDs и parent relations сохраняются;
- миграция сохранений не требуется.

## Проверки

- strict TypeScript domain, UI и test-check;
- сценарий производство → 24 бутылки → бар → смена;
- 730 дней регионального рынка;
- 82 дня сезонного первичного производства;
- 270 дней полного observer-run;
- сравнение SHA-256 полного состояния до и после оптимизации.
