# Feature Spec 027 — универсальные технологические отрасли

## Проблема

`TradeProductionBatchState` раньше означал одну абстрактную задержку между списанием сырья и появлением бутылок. Такой подход нельзя безопасно расширить на вино, дистилляты, выдержку, купажи, RTD и будущие коктейльные продукты.

## Пользователь и сценарий

Мир должен производить любые современные напитки по общим правилам. В будущем игрок сможет владеть производствами разных отраслей, поставлять собственные бутылки в бар и использовать их как ингредиенты коктейлей.

## Наблюдаемое поведение

- партия проходит последовательность технологических этапов;
- каждый этап имеет длительность, выход, оборудование, влияние на качество и крепость;
- результат этапа является промежуточным лотом и источником следующего этапа;
- выдержка уменьшает физический объём и сохраняет возраст;
- готовый товар появляется только после этапа розлива;
- фактический выпуск учитывает технологические потери;
- вино получает винтаж, выдержанный продукт — возраст;
- весь путь остаётся в traceability graph.

## Критерии приёмки

- [x] Все категории `BeverageCategoryId` имеют валидный blueprint.
- [x] Короткий RTD-цикл и длинный цикл виски используют один движок.
- [x] Есть промежуточные, maturation и blend сущности.
- [x] Производственная партия не создаёт товар до завершения процесса.
- [x] Объём не становится отрицательным и не увеличивается при выдержке.
- [x] Сохранения schemaVersion 21 мигрируют без потери товарных данных.

## Данные и состояние

`TradeState` остаётся владельцем коммерческого товара и партий. `TradeState.industrial` владеет:

- `IndustrialBatchPlan`;
- `IndustrialProcessRun`;
- `IndustrialIntermediateLot`;
- `IndustrialMaturationLot`;
- `IndustrialBlendRecipe`;
- историей технологических операций.

Каталог `data/industrialProcessCatalog.ts` задаёт процессы данными.

## API и контракты

- `startIndustrialBatch` создаёт план и первый этап;
- `advanceIndustrialProductionDay` двигает активные процессы;
- `industrialProductionSummary` даёт компактную проекцию для UI;
- `validateIndustrialProductionState` проверяет инварианты;
- kernel регистрирует технологические сущности и traceability edges, но не владеет их оперативным состоянием.

## UX

Новая основная вкладка не создаётся. Технологический цикл виден внутри карточки продукта и существующего производственного контекста.

## Производительность

- история ограничивается размерными окнами;
- observer-интеграция проверяет 270 автономных дней;
- многолетние процессы отдельно проверяются чистыми доменными тестами без полного мира;
- новые категории не требуют нового ежедневного обхода отдельного модуля.

## Миграция и откат

- schemaVersion 21 → 22;
- старые активные партии получают технологический план при нормализации;
- при откате данные `trade.industrial` игнорируются старой версией, но такой откат не должен сохранять игру поверх schemaVersion 23.

## Не входит в задачу

- ручное управление каждым клапаном;
- полноценное оборудование каждой отрасли в UI;
- сотни коктейльных рецептов;
- барные рабочие станции и посетители клуба;
- правовые спецификации конкретных защищённых наименований.
