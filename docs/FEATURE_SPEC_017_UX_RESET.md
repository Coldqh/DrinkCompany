# Feature Spec 017 — UX Reset

## Проблема

Интерфейс рос по числу подсистем и превратился в набор дублирующих панелей. Игрок видел устройство симуляции вместо понятных решений.

## Пользователь и сценарий

Игрок на телефоне открывает игру, сразу понимает, что требует решения, затем переходит в производство, торговлю или мир без поиска нужной панели.

## Наблюдаемое поведение

- нижняя навигация содержит четыре раздела и центральную кнопку дня;
- главный экран показывает только решения, текущую работу и деньги;
- производство собрано в поток сырьё → рецепт → партия → розлив;
- бренды, товары, заказы и покупатели находятся в торговле;
- мир содержит только карту, организации и группу;
- команда, финансы и сохранения открываются из меню компании;
- подробности открываются по контексту в модальных окнах;
- экран можно прокручивать вертикально;
- цветовая система ограничена чёрным, графитом, серым и бордовым.

## Критерии приёмки

- [x] не более четырёх постоянных разделов навигации;
- [x] не более трёх подвкладок на основном экране;
- [x] отсутствуют отдельные вкладки партий, команды и архива;
- [x] повторяющаяся статистика удалена с основных экранов;
- [x] все игровые действия остаются доступны;
- [x] старые сохранения не требуют миграции;
- [x] UI и домен проходят TypeScript-проверку;
- [x] существующие доменные тесты проходят без изменений.

## Негативные сценарии

- пустая компания без партий и сотрудников;
- много активных решений одновременно;
- длинные названия компаний и товаров;
- маленький экран 320 px;
- модальное окно с большим объёмом данных;
- обновление PWA поверх открытого сохранения.

## Данные и состояние

Схема сохранений не меняется. `schemaVersion` остаётся 13. Рефакторинг затрагивает только presentation layer.

## UX

Один экран отвечает на один вопрос. Карточка содержит максимум статус, две цифры и одно действие. Полные сведения открываются по нажатию.

## Не входит в задачу

Новые игровые механики, изменение баланса, изменение экономики и миграция доменных данных.
