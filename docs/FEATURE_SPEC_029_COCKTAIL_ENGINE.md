# Feature Spec 029 — Cocktail Engine

## Проблема

Hospitality-сектор умел списывать открытые бутылки, но использовал маленький жёстко заданный набор коктейлей и бесконечную абстрактную кладовую. Сложность рецепта, время приготовления, конкретный бренд, срок годности соков и реальный stockout не влияли на смену.

## Наблюдаемое поведение

- Каталог содержит 60 рецептов, которые читаются одним движком.
- Каждый рецепт задаёт точные количества и единицы, метод, лёд, бокал, гарниш, время и сложность.
- Категории напитков разрешаются в конкретные продукты с полки заведения.
- Разрешённая замена используется только при наличии подходящего продукта.
- Соки, сиропы, газировка, фрукты и гарниши расходуются из физических pantry lots.
- Pantry lots портятся, пополняются за деньги оператора и не уходят ниже нуля.
- Позиция снимается с продажи, когда не хватает хотя бы одного обязательного ингредиента.
- Время приготовления и сложность ограничивают число заказов за смену.
- Качество выбранных продуктов влияет на качество подачи, удовлетворённость и спрос.
- Себестоимость считается из фактически списанного товара.

## Критерии приёмки

- [x] Каталог содержит ровно 60 уникальных рецептов.
- [x] Рецепты валидируются против beverage categories и pantry catalog.
- [x] Меню хранит `recipeId`, конкретные `productId`, время, сложность и стоимость.
- [x] Pantry имеет количество, единицу, цену, получение и срок годности.
- [x] Продажа точно списывает миллилитры, граммы и штуки.
- [x] Пустой обязательный ингредиент отключает позицию с объяснимой причиной.
- [x] Смена ограничена физическим остатком и временем обслуживания.
- [x] Отчёт смены хранит pantry consumption, utilization и serve quality.
- [x] Старый hospitalityVersion 1 мигрирует в version 2.
- [x] GameState schemaVersion повышена до 24.

## Негативные сценарии

- неизвестная категория напитка;
- неизвестный pantry tag;
- несовпадающая единица измерения;
- пустая полка;
- пустая кладовая;
- недостаток денег на пополнение;
- испорченный pantry lot;
- нехватка времени станции;
- частичный остаток меньше одной порции;
- старое сохранение без pantry lots.

## Данные и состояние

- `CocktailRecipeDefinition` — неизменяемая спецификация рецепта;
- `CocktailPantryDefinition` — спецификация расходного ингредиента;
- `HospitalityMenuItemState` — конкретная реализация рецепта в заведении;
- `HospitalityPantryLotState` — физический остаток pantry;
- `HospitalityShiftItemState` — фактический расход и качество проданных порций.

## API и контракты

- Каталог не владеет товаром и деньгами.
- `TradeState` владеет закрытыми коммерческими продуктами.
- `HospitalityState` владеет открытыми ёмкостями, pantry lots, меню и сменами.
- Рецепт может ссылаться на product, beverage category или pantry tag.
- Любая категория перед продажей обязана разрешиться в конкретный product.

## Производительность

Подбор меню выполняется при создании и синхронизации заведения. Во время смены используются уже разрешённые ингредиенты. Каталог из сотен рецептов не требует отдельной ветки симуляции на рецепт.

## Миграция и откат

- schemaVersion 23 → 24;
- hospitalityVersion 1 → 2;
- для коктейльных заведений создаётся стартовая физическая кладовая;
- старые menu ingredients с `amountMl` нормализуются в `amount` + `unit`;
- откат на старую версию не должен сохранять игру поверх schemaVersion 24.

## Не входит в задачу

- редактор авторских коктейлей игрока;
- региональные тренды и сезонная мода;
- ручная мини-игра бармена;
- кухня ресторана;
- отдельный экран управления меню;
- полный каталог из сотен рецептов.
