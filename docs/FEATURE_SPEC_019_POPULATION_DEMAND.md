# Feature Spec 019 — Population and Demand Ecosystem

## Проблема

Продажи на полках рассчитывались из проходимости объекта и случайного шума. Население, доходы, каналы потребления, погода и поводы покупки не существовали как состояние мира. Legacy `WorldState.demandSignals` был вторым источником спроса.

## Наблюдаемое поведение

- каждый поддерживаемый регион имеет население и шесть потребительских сегментов;
- сегменты отличаются доходом, чувствительностью к цене, каналами и предпочтениями категорий напитков;
- ежедневный спрос зависит от погоды, выходных, зарплатных дней, туризма и региональных событий;
- бар, магазин и собственная точка игрока используют одну функцию спроса;
- каждая конечная продажа записывает регион, сегмент, повод и канал покупки;
- legacy-сигналы спроса вычисляются из `EcosystemState.demand`, а не изменяются отдельно;
- регионы и сегменты зарегистрированы в kernel entity registry.

## Критерии приёмки

- [x] одинаковый seed и день дают одинаковый спрос;
- [x] высокая цена снижает спрос чувствительных сегментов;
- [x] продажи не создают отрицательный товарный остаток;
- [x] observer-run на 1095 дней проходит без нарушений;
- [x] старые сохранения получают спрос через миграцию;
- [x] текущие сохранения используют schemaVersion 15.

## Негативные сценарии

- неизвестный регион использует безопасный fallback;
- отсутствие товара не создаёт покупку;
- нулевая продажа не попадает в журнал покупок;
- повреждённое старое demand-state пересоздаётся детерминированно.

## Данные и состояние

`EcosystemState.demand` владеет регионами, сегментами, ежедневными сигналами, событиями и покупками. `WorldState.demandSignals` является только совместимой проекцией для старого переговорного потока.

## Не входит в задачу

- индивидуальные жители;
- государственное регулирование;
- сельскохозяйственные урожаи;
- полноценные рестораны и клубы как отдельные типы объектов;
- рекламное влияние на знания потребителей.
